# Imported player character

`Documentation/PlayerCharacter.json` records source paths, preserved settings and validation status. `Assets/Resources/Characters/PlayerVisual.prefab` is an integration copy of the user's URP prefab, excluding only its gallery viewer behaviour. The original imported asset remains available. `ImportedPlayerBody` loads this resource; `FirstPersonMovement`, `PlayerControls`, `PlayerInteraction`, `LearningProgress` and the original CharacterController retain gameplay ownership.

The original humanoid model/material/textures and idle are used. Human Basic Motions FREE 2.4.2 supplies sixteen in-place Humanoid clips: eight directions each for walking and running. A generated resource controller uses two directional blend trees driven by actual player-local displacement. The original capsule, movement speed, camera, posture, input and interaction continue to own gameplay; root motion stays disabled. Sitting/lying/reach/fingers are adapted on the imported bones; there are no authored new motion clips. Read/Write is enabled on the FBX so head-weighted triangles can be excluded from a first-person skin. The original full skin casts shadows and appears in mirrors. Mesh variants are created once and destroyed with the player. There are no generated replacement body parts or old-avatar fallbacks.

- `python3 Tools/Characters/validate.py`: wiring, legacy removal, retained timing and task population.
- `python3 Tools/Lessons/validate_assets.py`: actual scene target populations/bindings and spoon-first order.
- Existing managed lesson checks cover saved progress and unchanged pickup/place timing math, now in `ManipulationMotion.cs`.
- `ImportedAvatarValidation.Run`: native smoke test, batch-only and requiring a `.avatar-smoke-project` marker in an isolated project. It opens an empty test scene, constructs a non-persistent test player and exits with a status/report. It must never run against the working scene or phone. Copy runtime scripts, character resource, model/animation/material/texture dependencies and required Unity packages into that isolated project first. The full interaction harness also checks the imported body when run separately.

Native smoke coverage: humanoid bones, original idle and sixteen directional clip references, retained height, URP material/albedo presence, first-person triangle filtering, mirror/main-view restoration, no demo/collision, finite standing/sitting/lying poses and finger movement. This is distinct from rendered appearance, object-specific hand contact, neck-edge quality, clothing clipping and actual phone RAM/FPS. Those remain device/visual review items. No player-profile restart or phone deployment is part of integration.

Height checks call `BakeMesh(mesh, true)` before transforming vertices to player space: Unity 6 compensates the renderer scale in this mode, avoiding double-counting its scale ([Unity API](https://docs.unity.cn/6000.6/Documentation/ScriptReference/SkinnedMeshRenderer.BakeMesh.html)).

Latest native run (2026-11-27, Unity 6000.6.7f1): passed; 54 bones, height 1.7599999 m, 30,682 full / 26,274 first-person triangles. Safe report is embedded in PlayerCharacter.json. Runtime and Editor compilation and asset/localization checks passed.

Directional controller regeneration: `Tools > DeutschRoom > Build Human Basic Motions Locomotion` (`PlayerLocomotionBuilder.Build`). It references original non-RM male Walk/Run FBX clips, keeps the original idle and preserves asset GUID on rebuild. No source imports, demo scenes or vendor models are altered. Sprint/jump/turn actions are not added. This package has no sitting, lying or pickup animation; those still use existing bone adaptation.

Latest directional native run (2026-11-27, Unity 6000.6.7f1): all sixteen directions selected their intended clip above 95% weight, animated the retargeted foot, kept bone poses finite and left the gameplay root fixed. Existing head/mirror/posture/finger checks also passed. No rendered appearance or device-performance claim follows from the headless test.

Palm contact fix (2026-11-27): the wrist target subtracts the imported rig's actual palm offset in its desired object-relative orientation. PickupItem caches handle-centre anchors for SpoonHandle/ForkHandle/KnifeHandle, or a near-edge bounds anchor for other shapes. TransformPoint includes item scale/rotation. Carry offset is (0.22, -0.32, 0.43) in camera space. Once pickup settles, the item follows the solved palm; placement and pickup animation paths are never overridden. Interaction LateUpdate precedes ImportedPlayerBody (execution order 100), so IK sees the current item pose.

Native result: 324 scaled-object/posture/look/rotation/locomotion cases passed a 2 mm palm-anchor tolerance, with no cumulative drift. Synthetic spoon geometry verifies handle rather than whole-object-centre selection. Guards verify no palm correction while placing or before pickup settles. This verifies numerical contact on the real imported rig, not object-specific finger silhouettes, penetration, or phone rendering.
