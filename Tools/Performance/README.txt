Memory regression checks

From the repository root (.NET 10):
dotnet run --project Tools/Performance/VoiceCacheChecks.csproj -p:BaseIntermediateOutputPath=/tmp/deutschroom-voice-cache/obj/ -p:OutputPath=/tmp/deutschroom-voice-cache/bin/

Compiles the actual Assets/scripts/GermanVoice.cs with managed Unity API doubles.
Checks count/estimated-byte LRU eviction, replay, oversized requested recordings,
protection of two simultaneous narrators, stop/completion/disable cleanup,
missing-recording text fallback, cached opening-recording availability, metadata-only
muted/preflight lookup and skipping/interruption of stale queued/active warnings.
This does not test Unity native allocation, audio playback or phone performance.

Native follow-up (Unity Profiler/Memory Profiler, same device/settings before and after):
Compare several minutes of lesson progression, replay/identification and case narration;
repeat scene entry/exit. Check AudioClip count/Audio memory, Mesh memory and GC Alloc.
Check audible narration on eviction/replay, both mirrors, jar pickup/placement,
upholstery appearance and blanket identification. Active recordings remain protected;
one oversized requested recording or simultaneous active recordings may exceed the
12-clip/8 MiB estimated decoded-PCM cache budget. This budget is not total app RAM.
Rendering, geometry and voice import quality are unchanged.

VoiceIntroA11Index.txt is regenerated by Tools/Voice/generate.py after installation.
Asset validation verifies it against the installed WAV keys. Current availability
checks avoid decoding queued recordings; playback keeps the bounded shared LRU.
Fixed touch geometry is cached across visibility changes, invalidated by safe-area
or resolution changes. Native resize/input/UI profiling remains required.
